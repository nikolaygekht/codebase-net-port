# Development steps

One folder per step, in order. The method is [`../DEV_APPROACH.md`](../DEV_APPROACH.md); this file is
just the index.

Start a step by copying the template:

```bash
cp -r claude/dev/_template claude/dev/001-step-name
```

**Every folder has its own number, and numbers are never reused.** An abandoned step keeps its folder
and gets a `SUMMARY.md` explaining why — that is a record, not clutter.

  and `SUMMARY.md` for the fixes. **Closed 2026-08-13** at 1054 tests: five real defects fixed, three of
  the audit's own claims overturned, and every remaining finding given a home.

  10 000 seeks through the C library and through `CodeBase.Net`, over the same table and the same query

| [`009-performance-audit`](009-performance-audit/) | — *(audit)* | **done** 2026-08-27; audit half closed 2026-08-19 | The first measurement of anything in this port: 10 000 seeks over a 10 000-record table, run through the reference C library and through `CodeBase.Net`, against the same file and the same query sets — with matching per-record checksums proving both did identical work. **No change to `net/`.** Like-for-like the port is **1.36–1.43× the C's time per seek**, and it walks a tag **2.45× faster**, which removes suspect P4. The finding that reorders the rest: the C library's block cache — off unless `code4optStart` is called — is worth **14×**, far more than everything else on the suspect list combined, so **P1 dominates**. P2 confirmed and quantified at **~3 956 bytes allocated per seek**, though not attributed between the two candidates. P6 and P7 not exercised, and said so. **`ANALYSIS.md` then decomposed the 14×**: it is read syscalls at a measured 1.18–1.21 µs each and nothing else, against a hash-and-`memcpy` hit at 0.002 µs — and the same win is available here, **11.6× on a seek and 23.4× on a walk**, measured by giving the port a perfect cache. With I/O out of both sides the port's own CPU work is **1.4–1.7× the C's and 1.7× faster on a walk**, and the residual is P2: a fresh `byte[keyLength]` materialised for every comparison, worth 1.7–1.9× of the descent to remove. Also closed finding 6 (entries per leaf, and both leaf searches are linear), showed P7 changes nothing on unique keys, and carries a **retraction of its own first pass**, whose RAM-backed numbers never left tier-0 JIT. **Remediation designed, planned and executed 2026-08-21 to 2026-08-22** — eight sub-steps, the eighth unplanned. The cache decorates `IRandomAccessSource` rather than the index (a walk's reads are 96% DBF) and is **optional on the reference's own three-valued policy**, `Off`/`WhenExclusive`/`Always`, defaulting to the C's `OPT4EXCLUSIVE` — so today's default caches nothing and starts by itself when `LOCKING` arrives. Landed: compare-in-place, the padded comparison, `BlockResidency`/`BlockPool`, the cache itself, `Table.Refresh()`, the shared-cache lock and the concurrent-use detector, a benchmark project and a profiling driver. **The eighth sub-step is the one to read**: every gate had passed and the step was still wrong about where its time went for the third time — the answer was a `RandomAccess.GetLength` **per block read**, four per descent with the cache fully warm, **87% of a cached descent**, invisible to the audit because a metadata call is not a read (**ADR-35**). Removing it took a cached seek to **732 ns** and an uncached one to **5 637**, so the audit's predicted **11.6× for the cache is met** after standing at 2.13×; the same call was ~25% of a cached walk and **90% of the memo path**, which had never been measured at all. Against the C, with a new `go-skip` control: **parity or better when the work is I/O, a consistent ~1.85× when it is CPU**, and a seek costs **5.41×** a plain positioning where the C's own ratio is 5.84×. What found it was counting reads and `Length` queries rather than timing. **Closed 2026-08-27** with the decisions recorded as **ADR-36** (the cache decorates the source, one pool per engine), **ADR-37** (the three-valued policy, and why the default caches nothing), **ADR-38** (the invalidation surface, and the block that lives in two places — which contradicts `ANALYSIS.md` §9), **ADR-39** (eviction as a pure class in the reference's priority order), **ADR-40** (the project's first performance gate, at 2×, retargeted onto read counts) and **ADR-41** (the threading contract, the detector, and the library's first lock). 1333 tests at close, 566 golden. Deferred rather than written: rent-and-return with the window as the residency unit, because it describes a zero-copy design that was not built |
| [`010-expr`](010-expr/) | `EXPR` | **done** 2026-09-03 | The expression engine, and the end of the last thing `CDX-READ` was waiting for: **a tag stops having to be a bare field name**. 1909 tests at close, 639 golden, **no golden expectation changed**. The gate is seven assertions and every one holds: the **193-row function table** row for row against the C's own; the parse pass as a **shape** against the reference's `E4INFO` arrays; resolution's `(row, length)` per node over 212 expressions with **144 of 193 rows oracle-gated and 49 declared unreachable**; the refusals with the C's exact codes; **raw result bytes for 131 constant expressions and 77 field expressions at all 16 records**; **every stored key of every `CDXEXPR` tag — 22 tags, 338 keys, byte for byte**; and end to end, each tag walking the records the reference stored in its order. **ADR-28's refusal is gone.** And the **thirteen functions Visual FoxPro has that CodeBase refuses** are supported (**ADR-43**) and gated by Visual FoxPro itself, run offline in a VM (**ADR-44**) — the only oracle there can be, since the corpus generator *is* the engine that refuses them: 36 values compared on stored bits and 16 tag key lengths against VFP's own headers, which answers ADR-43's named risk that a length computed from the operand might not be the length VFP wrote. They live in a **second row band** past the terminator, so the transcribed 193 stay exactly 193 and row coverage reports **three** counts rather than one. Five of their rules are not what a reader would guess and all five are witnessed in stored bits: `MOD` takes its sign from the divisor, `INT` truncates towards zero and stores a **positive** zero for `INT(-0.5)`, `ROUND` rounds the decimal digits, `AT` counts from one, and `MIN`/`MAX` are variadic with a string form. The seventh assertion, the query optimizer's contract, is the one part with **no oracle** — the reference exposes none of it through a dump — so the corpus supplies the cases and not the answers, and the is-constant predicate is checked against the evaluator's own behaviour rather than against a copy of its rule: whatever it calls constant must evaluate with no record, and whatever reads a field must not be called constant. Built in eight sub-steps behind a two-axis gate designed before any code — semantics C#-authored and tested over *constants*, key bytes driven from the C's *recorded value* so the two cannot cancel — and the design's own prediction held: skipping the `hasTrim` rewrite reddens axis B only, on `TRIM(K_TEXT)`'s keys **and only those**. Findings the reading would not have given: the parse pass **removes nodes** when it folds a constant parameter, so `STR(K_NUM,12,3)` is two nodes not four; **promotion rewrites a row and adds no node**, writing its length to the simulated stack and never to the node, so a promoted numeric field still reports the field's width — which corrected `DESIGN.md`; the **inclusive comparisons do not break a tie on width while the strict ones do**, so `"AAAA" > "AAA"` and `"AAAA" <= "AAA"` are both true, found by the only **two records in the corpus** that distinguish it; **`STR` rounds the decimal digits and not the binary value**; and a **memo operand is NUL-padded**, which makes it key as though trimmed. The corpus was sized by row coverage rather than taste: the resolution gate found **46 reachable rows nothing reached**, a second generator run added them, every case landed on the row it was written for, and the corpus regenerated byte-identical except the expression dump. Twenty-three mutations across the nine sub-steps, including the wrapper-node promotion that proves the gate's sequence equality. Decisions: **ADR-42** the explicit date policy, **ADR-43** VFP's functions, **ADR-44** the VFP oracle, **ADR-45** prefix `=` and division by zero, **ADR-46** the optimizer's contract, **ADR-47** the table before the scanner |
| [`011-query-optimizer`](011-query-optimizer/) | `QUERY` | **in progress** — sub-steps 1-6 of 9 done, 2026-09-04 | **The bitmap query optimizer — the thing the whole port exists for.** A filter expression over one table becomes a record set produced by seeking tags instead of scanning: decompose the compiled expression into per-tag range constraints, merge them, answer each by a CDX seek, combine the record-number sets, and re-evaluate per candidate only the terms no tag could answer. Designed against [`specs/QUERY-OPTIMIZER.md`](../specs/QUERY-OPTIMIZER.md), which step 010 was already built to satisfy — `OptimizerContractGoldenTests` gates all four things §3 asks of the compiled form, so the retained node table, operator classification by row band, evaluate-at-a-node and a tag that keeps its `CompiledExpression` need no work here. **The gate is two checks that fail differently, and neither is skippable**: full-scan equivalence, which needs no reference at all and runs on every case in both tag scopes, and the reference's own answers at **four depths** — a discovery of the design pass, since `RELATE4`/`RELATION4` are public in `R4RELATE.H`, so the generator can dump the tag matched to each node, `fullyMapped`, **the candidate bitset before any residual filtering**, and the final record sequence and count. Depth 3 is the one that matters: it compares the set a decomposition error cannot hide from. Two decisions taken at design time and already recorded — **ADR-52**, eligibility replicates CodeBase's four refusals by default and widens type and collation under `QueryTagScope.AllSeekable` (filter and unique are never widened, because they are structural), and **ADR-53**, the reference's `tagPos = 1` assignment is not replicated but its intent is. Both close ADR-46. Reading the C during design also **resolved `QUERY-OPTIMIZER.md` §12 item 2** — the partial-string widening's apparent asymmetry is exactly the two branches that write the `gt` slot, and they are the only two that write it, so it is not a second defect — and found that **`log4true` reads the wrong positions**, trusting a term only when `-1` or `-2` matched a tag, which are the operand roots only if the right operand is one node; where they are not, the reference re-evaluates a term its own bitmap answered. The port trusts per term instead, and depth 4 is what proves the divergence is the safe direction. Nine sub-steps; the first is the oracle and writes no C# of the optimizer, as step 010's did |
